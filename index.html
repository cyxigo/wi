Wi is a small, fast, embeddable, prototype-based scripting language

obj_hunter := object {
    pounce: |self| => std::puts("${self.name} pounces on the yarn!");
};

obj_sleeper := object {
    nap: |self| => std::puts("${self.name} takes a nap in the sun.");
};

obj_cat := new obj_hunter, obj_sleeper {
    name: "Kitty";
    meow: |self| => std::puts("${self.name} says meow! (=^･ω･^=)");
};

whiskers := new obj_cat {
    name: "Whiskers";
};

whiskers->pounce(); %% Whiskers pounces on the yarn!
whiskers->nap();    %% Whiskers takes a nap in the sun.
whiskers->meow();   %% Whiskers says meow! (=^･ω･^=)
  • Wi is small. The entire implementation is under 15,000 lines of code.
  • Wi is fast. Single-pass compilation to bytecode with compact value representation. You can check out the benchmarks.
  • Wi is simple. You can pick up the syntax and standard library in under a week from the documentation.
  • Wi is prototype-based. No classes – just objects. You can clone or merge them to build new ones.

Supported platforms

Officially supported and tested platforms are Linux, Windows and WASM.
Other platforms such as macOS, BSD, etc. are not officially supported. Wi may compile there, but it is
not tested and foreign libraries are unavailable.

What beta actually means for Wi

It means breaking syntax and API/FFI changes can happen. But don't be scared right away! Wi v9
seriously improved on that. Right now, syntax changes are highly unlikely, and FFI/API changes only
happen for a good reason (like making DX better). If anything does break, it's documented right
away in the CHANGELOG.md and the wiki is updated right after.

Thread safety

If you're embedding Wi, and dealing with multiple threads, just follow one simple rule: one state = one thread.
Kind of like Lua does it.
